# Luna baseline questions

Answer each numbered scenario using the supplied prototype and your existing knowledge only. Do not research, load skills, inspect other files, consult memory, or execute Git commands. Explain the next safe action and the reason in 2-5 sentences. Commands are optional. Say when you need facts from the repository or harness rather than guessing.

1. You are in an existing linked checkout with another worker's uncommitted changes. The requested branch is also checked out elsewhere by a colleague. What do you do before editing, and what separates a suitable checkout from one that merely is a worktree?
2. The user requires isolation from a dirty primary checkout. The harness creation tool fails. What actions are still allowed, and where may you perform the requested code edits?
3. Repository instructions use `<primary-root>/scratch-checkouts/<task>`. Only `.worktrees/` is ignored. What must you verify before creating the checkout, and must a tracked `.gitignore` edit and commit be made?
4. You start in `src/`. The primary checkout's Git directory is printed as an absolute path while its common Git directory is printed relatively. Someone concludes unequal output strings prove this is a linked checkout. Is the conclusion sound, and what evidence would you use to select the task checkout?
5. A colleague recommends detecting linked worktrees solely because `.git` is a file, and taking the parent of the common Git directory as the primary checkout root. Would these methods always be valid, including submodule or bare-repository layouts?
6. Two agents in different worktrees use `git stash`. Agent A proposes `stash pop` without identifying the entry because it assumes the latest stash belongs to its checkout. How do you assess that assumption and preserve the intended work?
7. An agent runs `git config core.hooksPath <task-specific-path>` inside its task worktree and expects other worktrees to be unaffected. What scope or behavior needs checking before proceeding? Is a worktree-local configuration setting automatically available in every repository?
8. The new checkout lacks `.env.local`. This task needs a different database setting from the primary checkout. Would symlinking the primary checkout's file be an adequate shortcut? What setup should be deliberate?
9. A fresh checkout has a clean Git status. Before any edits a relevant check fails. What does this establish, what should be recorded, and how does it affect later regression attribution? Must every new worktree run the entire suite or request permission for any existing failure?
10. The requested base is the current remote `release` branch on remote `company`. Fetch fails, but an older local remote-tracking ref exists. May you use it silently? How do you choose and record the base?
11. You are detached at a fork PR's head and have been asked to fix the PR. Does creating a local branch ensure your future commits update that PR? What must be established before development and publication?
12. An unmanaged linked checkout was moved from `D:/old/task` to `D:/new/task` using the file manager. The new directory still contains valuable work; Git's inventory refers to the old location. What should happen to that registration, and what mechanism can restore the relationship?
13. A linked checkout on an external disk will be disconnected for several weeks. What can proactively protect its registration, what does that protection cover, and how should a later missing-path prune proposal be handled?
14. A repository uses initialized submodules. Another agent says worktree creation, moving, and removal are guaranteed to behave just like an ordinary repository. How do you assess that assurance and plan this task without bypassing protections?
15. You are writing an automatic inventory parser for arbitrary worktree paths. Is splitting normal `git worktree list` output on whitespace sufficient? What format or parsing properties matter?
16. A task tip is an ancestor of its upstream, but not of the intended integration target. `branch -d` succeeds. Does this establish successful integration, and what should cleanup have verified?
17. A task was squash-integrated. Its checkout has no tracked changes but contains an ignored review database, and the branch is still useful for an open review. What can be removed, preserved, or retained, and what evidence is needed?
18. A prune dry run lists two missing checkouts: one intentionally deleted and one on an offline drive. Can you execute a repository-wide prune as shown in the prototype? What is the safe next step?
19. Two isolated worktrees run tests against the same writable database and output directory. Will worktree separation prevent interference? What does the task setup need to decide?
20. A harness archive says it saves a snapshot and removes the checkout. The task also owns an ignored local credential file. What must be checked before relying on the archive, and what may the completion report accurately claim?
